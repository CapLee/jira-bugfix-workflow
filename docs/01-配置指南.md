# 01 · 配置指南

## 1. 环境要求

- Python **3.8+**（只用标准库，无任何 pip 依赖）
- 能访问 JIRA 的网络（内网/VPN 均可），终端可用（Windows 推荐 git-bash / PowerShell / VS Code 终端，避免旧版 cmd.exe 中文代码页问题）
- JIRA 版本：Server / Data Center 8.x（HTTP Basic）为主；Bearer token 与 Jira Cloud 见 §6

整个工具 = `scripts/jira.py` 单文件，拷到任何目录即可运行，不需要装 skill、不需要 IDE。

## 2. 配置凭据（一次性）

工具用 **HTTP Basic 认证**（或 Bearer token）调用 JIRA REST API，凭据放在本地文件里，脚本自动读取、永不打印。

### 凭据文件模板

```yaml
# jira-api-creds.yaml
base_url: https://ticket.你的公司.com
username: 你的JIRA登录名
password: 你的密码
# —— 以下为可选键 ——
# token: xxxxxx     # Bearer 认证（JIRA Server PAT）；与 username/password 二选一，同时存在时 token 优先
# insecure: true    # 跳过 HTTPS 证书校验（默认失败后已自动降级重试，一般不需要写）
# timeout: 60       # 请求超时秒数（默认 60）
```

### 文件放哪里（四种方式）

| 方式 | 路径 | 适用 |
|---|---|---|
| 默认（Windows） | `%LOCALAPPDATA%\hermes\jira-api-creds.yaml` | Windows 本机单实例 |
| 默认（macOS/Linux） | `~/hermes/jira-api-creds.yaml` | 非 Windows 单实例 |
| 环境变量指定 | `export JIRA_CREDS_PATH=/任意路径/creds.yaml` | 临时指向 / 脚本化 |
| **profile（多实例推荐）** | `%LOCALAPPDATA%\hermes\jira-profiles\<名字>.yaml`，用 `--profile <名字>` 调用 | 同时用多套 JIRA/多账号 |

### profile：多实例 / 多账号（v2 新增）

同事常见的用法：一套连公司生产 JIRA、一套连测试环境、一套连其他公司/项目的 JIRA——**一个环境一个文件，名字即开关**：

```
%LOCALAPPDATA%\hermes\jira-profiles\
├── company-prod.yaml      # 每份内容和普通凭据文件一样（三行起）
├── company-test.yaml
└── other-corp.yaml
```

```bash
python3 scripts/jira.py --profile company-prod whoami     # 连生产
python3 scripts/jira.py --profile company-test search ... # 连测试
```

- profile 目录可用环境变量 `JIRA_PROFILES_DIR` 改到别处（团队共享盘除外，凭据别上共享盘）
- 不想每次敲 `--profile`：`export JIRA_PROFILE=company-prod`
- 找不到 profile 时脚本会**列出可用的名字**，不用翻目录
- 规则：`--config`（指具体文件）与 `--profile`（指名字）二选一；都不给时按 `JIRA_CREDS_PATH` → 默认路径

### 常见坑（重要）

1. **别把模板的尖括号一起填进去**——写成 `<你的登录名>` 会导致认证失败。脚本会自动剥掉误留的成对 `<>`/引号，但最好填干净
2. **密码含 `#`**：解析器只在「# 前有空格」时当注释。密码 `abc#def`（# 前无空格）安全；`abc #def` 会被截断——避免后一种写法
3. **密码不要写进聊天/邮件/文档**，仅留在本机凭据文件
4. 配好后可把凭据文件加入 `.gitignore`（仓库已内置 `*creds*.yaml` 规则），防止误提交
5. `token` 与 `username/password` 同时写时 **token 优先**（走 Bearer），避免配了 token 还疑惑为什么没用密码

## 3. 冒烟验证

```bash
python3 scripts/jira.py whoami
# 身份: 张三 (name=zhangsan, email=zhangsan@corp.com)
# 实例: https://ticket.你的公司.com（凭据: …\jira-api-creds.yaml，认证: basic）

python3 scripts/jira.py search --jql 'assignee in (currentUser()) order by updated DESC' --max 3
```

**成功**：whoami 输出身份+实例两行；search 输出表格（KEY/类型/状态/优先级/经办人/更新/摘要）。
**失败排查**：

| 现象 | 原因与处理 |
|---|---|
| `[错误] 凭据文件不存在: …` | 文件路径不对，用 `JIRA_CREDS_PATH` / `--profile` 指定或建到默认路径 |
| `认证失败 HTTP 401` | ① 用户名/密码错（含误留 `<>`）② 账号被 SSO 锁/无密码（该实例不支持 Basic）③ 用户名格式（LDAP 名 vs 邮箱） |
| `找不到 profile「xx」` | 按报错里列出的可用名字建文件；profilename 与文件名必须一致 |
| `网络错误: …` | 内网/VPN 不通；证书自签会**自动降级不校验重试**（有警告行） |
| `[重试] HTTP 503 …` | 服务端抖动，脚本自动重试（最多 2 次）；持续失败再查网络/VPN |
| 中文乱码 | 换 git-bash/PowerShell 终端；脚本已内置 UTF-8 输出 |

## 4. 切换 JIRA 实例

| 方式 | 做法 | 场景 |
|---|---|---|
| 改 `base_url` | 直接编辑凭据文件 | 只用一个实例，偶尔切测试/生产 |
| profile（推荐） | 每实例一份文件 + `--profile 名字` | 多实例并存、团队多人各配各的 |
| `JIRA_CREDS_PATH` | 每实例一个路径，运行时 export | 脚本化/CI |

> 防串库：所有**写操作**（start/resolve/assign/comment）的输出都会带 `@ https://当前实例`，执行前扫一眼就不会把 A 环境的单操作到 B 环境。

## 5. 安全说明

- 凭据只在本地文件；脚本不打印、不上传、不写日志
- 写操作三保险：`--dry-run` 预演（零写请求）→ 执行 → 自动读回验证
- 建议给凭据文件设置仅本人可读权限（Unix: `chmod 600`）；profile 目录同理
- 别再写第二份「共享凭据」发同事——每人配自己的，出问题可追溯到人

## 6. 认证方式（Basic / Bearer / Cloud）

| 目标 | 配置写法 | 说明 |
|---|---|---|
| JIRA Server / DC（默认） | `username` + `password` | HTTP Basic |
| Server PAT（8.14+/DC） | `token: xxxxxx` | Bearer 认证，token 优先于密码 |
| Jira Cloud | `username: 你的邮箱` + `password: API Token` | Cloud 的 REST 基本同构，user 字段差异见 docs/03 §4 |

一个实例一个 profile 文件，认证方式跟着文件走，互不影响。
