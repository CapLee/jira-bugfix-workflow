# 01 · 配置指南

## 1. 环境要求

- Python **3.8+**（只用标准库，无任何 pip 依赖）
- 能访问 JIRA 的网络（内网/VPN 均可），终端可用（Windows 推荐 git-bash / PowerShell / VS Code 终端，避免旧版 cmd.exe 中文代码页问题）
- JIRA 版本：Server / Data Center 8.x（REST Basic 认证）；**Jira Cloud 不适用**（认证方式不同，见文档 03）

整个工具 = `scripts/jira.py` 单文件，拷到任何目录即可运行，不需要装 skill、不需要 IDE。

## 2. 配置凭据（一次性）

工具用 **HTTP Basic 认证**调用 JIRA REST API，凭据放在本地文件里，脚本自动读取、永不打印。

### 凭据文件模板

```yaml
# jira-api-creds.yaml
base_url: https://ticket.你的公司.com
username: 你的JIRA登录名
password: 你的密码
```

### 文件放哪里（三选一）

| 方式 | 路径 | 适用 |
|---|---|---|
| 默认（Windows） | `%LOCALAPPDATA%\hermes\jira-api-creds.yaml` | Windows 本机 |
| 默认（macOS/Linux） | `~/hermes/jira-api-creds.yaml` | 非 Windows |
| 环境变量指定 | `export JIRA_CREDS_PATH=/任意路径/creds.yaml`（每次运行前 export，或写进 shell 配置） | 最灵活，推荐多人/多实例场景 |

### 常见坑（重要）

1. **别把模板的尖括号一起填进去**——写成 `<你的登录名>` 会导致认证失败。脚本会自动剥掉误留的成对 `<>`/引号，但最好填干净
2. **密码含 `#`**：解析器只在「# 前有空格」时当注释。密码 `abc#def`（# 前无空格）安全；`abc #def` 会被截断——避免后一种写法
3. **密码不要写进聊天/邮件/文档**，仅留在本机凭据文件
4. 配好后可把凭据文件加入 `.gitignore`（仓库已内置 `*creds*.yaml` 规则），防止误提交

## 3. 冒烟验证

```bash
python3 scripts/jira.py search --jql 'assignee in (currentUser()) order by updated DESC' --max 3
```

**成功**：输出表格（KEY/类型/状态/优先级/更新/摘要）。
**失败排查**：

| 现象 | 原因与处理 |
|---|---|
| `[错误] 凭据文件不存在: …` | 文件路径不对，用 `JIRA_CREDS_PATH` 指定或建到默认路径 |
| `认证失败 HTTP 401` | ① 用户名/密码错（含误留 `<>`）② 账号被 SSO 锁/无密码（该实例不支持 Basic）③ 用户名格式（LDAP 名 vs 邮箱） |
| `网络错误: …` | 内网/VPN 不通；证书自签会**自动降级不校验重试**（有警告行） |
| 中文乱码 | 换 git-bash/PowerShell 终端；脚本已内置 UTF-8 输出 |

## 4. 切换 JIRA 实例

改凭据文件里的 `base_url` 即可（例如测试环境 → 生产环境）。只要目标实例是 JIRA Server/DC 8.x 且你的账号能用 Basic 认证，其余全部运行时自动适配。

## 5. 安全说明

- 凭据只在本地文件；脚本不打印、不上传、不写日志
- 每次状态写操作后自动读回验证，操作可追溯
- 建议给凭据文件设置仅本人可读权限（Unix: `chmod 600`）
