# 07 · 多实例与协作场景指南

> 写给「不只是处理自己名下的单」的人：换 JIRA 环境、多账号、帮同事改单、转派交接。
> 基础用法先看 docs/02、docs/04；本页全是 v2 新增能力的完整剧本。

## 场景一：同时用多套 JIRA / 多账号（profile）

**痛点**：改 `base_url` 来回切容易搞混，还可能把 A 环境的操作发到 B 环境。

**做法**：一个环境一个文件，名字即开关。

```bash
# 1) 建 profile 目录（Windows；macOS/Linux 是 ~/hermes/jira-profiles）
mkdir -p "$LOCALAPPDATA/hermes/jira-profiles"

# 2) 每个环境一份（文件名 = profile 名）
#    company-prod.yaml / company-test.yaml / other-corp.yaml …
cat > "$LOCALAPPDATA/hermes/jira-profiles/company-prod.yaml" <<'EOF'
base_url: https://ticket.你的公司.com
username: 你的登录名
password: 你的密码
EOF

# 3) 用 --profile 切换（或在会话里 export JIRA_PROFILE=company-prod 定成默认）
python3 scripts/jira.py --profile company-prod whoami
python3 scripts/jira.py --profile company-test search --jql 'project = TEST order by updated DESC'
```

要点：

- 打错名字不用翻目录——报错会把**可用 profile 名字列出来**
- `--profile`（名字）和 `--config`（具体文件路径）二选一；都不给时走 `JIRA_CREDS_PATH` → 默认凭据文件
- 防串库三招：① 多环境一律用 profile，别共用一份文件；② 写操作输出都带 `@ https://当前实例`，执行前扫一眼；③ 拿不准先 `whoami`
- Server PAT / Cloud 的写法差异见 docs/01 §6
- profile 目录可用 `JIRA_PROFILES_DIR` 指到别处（**别放共享盘**，凭据只留本机）

## 场景二：同一 JIRA 里的多个项目

不用任何配置——JQL 换 `project` 就行：

```bash
python3 scripts/jira.py search --jql 'project = BPM AND resolution = Unresolved AND assignee in (currentUser())'
python3 scripts/jira.py search --jql 'project = FRONT AND status = Working AND resolution = Unresolved'
```

或者直接在 JIRA 网页调好过滤器，**复制地址栏链接**丢给工具：

```bash
python3 scripts/jira.py search --url 'https://ticket.你的公司.com/issues/?jql=project%20%3D%20BPM%20AND…'
```

> 注意别贴 `…/browse/BPM-123` 这种单页链接（不含 JQL，工具会提示）。要贴的是 `/issues/?jql=…` 过滤器地址。

不确定项目 key？`projects --query 关键词` 查。

## 场景三：改别人的 bug（接手 / 支援）

典型来历：同事休假、转岗；测试催得急；组长让你兜底。**核心差异：单子经办人不是你，工作流可能不让你流转。**

### 3.1 找到他们的单

```bash
# 按人（登录名或显示名）
python3 scripts/jira.py search --jql 'assignee = zhangsan AND resolution = Unresolved order by updated DESC'
# 或整项目扫一遍，看经办人列挑人
python3 scripts/jira.py search --jql 'project = STRUCTURING AND resolution = Unresolved'
```

### 3.2 先探路：这张单我动得了吗？（零风险）

```bash
python3 scripts/jira.py transitions STRUCTURING-118
```

三种结果：

| 结果 | 含义 | 下一步 |
|---|---|---|
| 有一堆流转（接受/解决…） | 权限够，直接干 | 照常 start / resolve |
| **空列表** / `[错误] 当前账号对 X 无任何可用流转` | 工作流限制（通常只有经办人能流转） | 走 3.3 接管 |
| 报 403 或无权限看单 | 连读都不行 | 找 JIRA 管理员或请对方转给你 |

也可以在写之前先 `resolve KEY … --dry-run`——它会告诉你可用流转和将填的字段，全程零写请求。

### 3.3 接管（把单转到自己名下）

```bash
python3 scripts/jira.py assign STRUCTURING-118 --to me
# 已指派 STRUCTURING-118 → Ronnie Li(李一鸣) (name=…) @ https://…；读回: Ronnie Li(李一鸣) ✓
```

- 接管 = 改经办人，JIRA 会记录变更历史（转派是公开动作，**按团队约定来**：有的团队要求先跟原负责人打招呼）
- 想直接转给别人（不是自己修）：`assign STRUCTURING-118 --to "目标人"`；名字不确定可先 `assign … --to me --dry-run` 试手感
- 找不到人时报错会说明「该人不属于本项目 assignable 用户」——换登录名试试

### 3.4 修复 → 接受 → 解决

接管后就是标准流程（docs/02 §2）：

```bash
python3 scripts/jira.py issue STRUCTURING-118 --save D:/tmp/118.md   # 读单（含评论历史）
# …在代码仓库里定位修复 + 自验证…
python3 scripts/jira.py start STRUCTURING-118                        # 接受
python3 scripts/jira.py resolve STRUCTURING-118 \
  --impact "…" --cause 逻辑边界遗漏 --solution 增加边界处理 --prevention 无需额外措施 \
  --field "修复的版本=V1.0.0_1"
```

**交回给谁**，按约定选一种：

| 情况 | 做法 |
|---|---|
| 走测试验收 | 多数工作流 resolve 后自动转报告人（=原测试）；不自动的话加 `--assign "测试员"` |
| 修完还给原负责人跟进 | `assign STRUCTURING-118 --to "原负责人"` |
| 拿不准 | 先在评论里说明，让用户/组长拍板 |

### 3.5 协作评论（对接上下文，别只在自己脑子里）

```bash
python3 scripts/jira.py comment STRUCTURING-118 --body "已定位：进页面时默认选中逻辑缺失，修复中，预计今天提交"
python3 scripts/jira.py comment STRUCTURING-118 --body "[~zhangsan] 这块原先是你跟的，有个边界问题想确认：…"
```

- `[~登录名]` 是 JIRA wiki 的 @人语法（对方收到邮件通知——**发之前先确认内容**）
- 长内容用 `--body-file 文件.md`；执行后按评论 id 读回验证
- 好习惯：接管时留一句「XX 休假，我代为处理」；流转前留「已修复，见提交 abc123」

### 3.6 一条完整命令链（照抄版）

```bash
P="python3 scripts/jira.py"
URL='https://ticket.你的公司.com/issues/?jql=project%20%3D%20STRUCTURING%20AND%20assignee%20%3D%20zhangsan'

$P search --url "$URL"                      # ① 看同事的单
$P issue STRUCTURING-118 --save 118.md      # ② 读单
$P transitions STRUCTURING-118              # ③ 探路：能不能流转
$P assign STRUCTURING-118 --to me           # ④ 不能 → 接管
$P comment STRUCTURING-118 --body "代为处理，从今天开始"   # ⑤ 留痕
# —— 改码 + 自验证 ——
$P start STRUCTURING-118                    # ⑥ 接受
$P resolve STRUCTURING-118 --impact "…" --cause … --solution … --prevention … --dry-run  # ⑦ 预演
$P resolve STRUCTURING-118 --impact "…" --cause … --solution … --prevention …            # ⑧ 正式
```

## 场景四：把我的单转给别人 / 批量转派

```bash
# 单张转派
python3 scripts/jira.py assign BPM-1597 --to "张三"

# 批量转派（先把清单拉出来核对，再逐张转）
python3 scripts/jira.py search --jql 'project = BPM AND status = 未开始 AND assignee in (currentUser())' --format md
for k in BPM-1618 BPM-1600; do python3 scripts/jira.py assign "$k" --to "张三"; done
```

转派前建议 `comment` 一句背景（"这单归口调整给张三，上下文见评论"），转完让用户确认对方已收到。

## 团队协作约定（建议）

1. **写操作永远慢一拍**：start / resolve / assign / comment 先 `--dry-run` 给用户过目（打印完整 payload，零写请求），确认后执行，执行后读回验证
2. **接管要有据**：assign 是公开的变更记录；先经用户/原负责人同意再动手
3. **评论留痕**：接管、关键定位、交接都留一条评论，别人（和未来的你）能接上上下文
4. **多环境不共凭据**：一人一份 profile；写操作前顺手扫一眼输出里的 `@ 实例`
5. **词表别硬背**：每次以运行输出为准；跨项目/跨环境自动发现

## 速查表

| 我想干嘛 | 命令 |
|---|---|
| 看同事手上的单 | `search --jql 'assignee = 名字 AND resolution = Unresolved'` |
| 试这张单能否流转 | `transitions KEY` / `resolve KEY … --dry-run` |
| 接管别人名下的单 | `assign KEY --to me` |
| 转派给某人 | `assign KEY --to "姓名"` |
| 留协作评论 / @人 | `comment KEY --body "…"`（@人 `[~登录名]`） |
| 换环境 / 换账号 | `--profile 名字`（或 `export JIRA_PROFILE=名字`） |
| 贴过滤器链接直接拉单 | `search --url '…/issues/?jql=…'` |
| 确认当前连的是哪台 | `whoami` |
| 预演任意写操作 | 加 `--dry-run` |
