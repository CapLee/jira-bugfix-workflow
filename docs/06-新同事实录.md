# 06 · 新同事实录：从安装到交单（角色扮演版）

> 你工位上，同事甩给你一个链接：「JIRA 处理 bug 的工具，试试」。下面是你从零开始的完整过程——
> 每步都有「屏幕上会看到什么」，照着敲就行。假设你用 Windows + git-bash（Mac/Linux 把 `python` 换成 `python3`）。

---

## 第 0 幕 · 先看看电脑里有没有 Python（1 分钟）

打开终端（git-bash / PowerShell / VS Code 终端），敲：

```bash
python --version
```

- 看到 `Python 3.8+` 之类 → 过关，继续
- 提示「找不到 python」→ 去 python.org 下载装一个，安装时**勾上 Add Python to PATH**，重开终端再试

## 第 1 幕 · 把工具箱领回家（1 分钟）

```bash
git clone https://github.com/CapLee/jira-bugfix-workflow.git
cd jira-bugfix-workflow
```

屏幕上会出现一个 `jira-bugfix-workflow` 文件夹。里面两个东西最重要：

- `scripts/jira.py` —— **工具本体**（就一个文件）
- `docs/` —— 说明书（看不懂命令时翻 `docs/05-大白话速通版.md`）

## 第 2 幕 · 办「门禁卡」（2 分钟，只办一次）

工具要替你登录 JIRA，得有你的账号密码。存在你自己电脑的一个小文件里，叫门禁卡。

**最省事：让向导帮你办卡**（顺带登记项目、设当前项目，推荐）：

```bash
python scripts/jira.py init
```

也可以手工办卡（下面这样）：

```bash
mkdir -p "$LOCALAPPDATA/hermes"
notepad "$LOCALAPPDATA/hermes/jira-api-creds.yaml"
```

记事本里粘贴这三行，把尖括号里的内容换成你自己的：

```yaml
base_url: https://ticket.你的公司.com
username: 你的JIRA登录名
password: 你的密码
```

三个格子分别填什么（大白话）：
| 格子 | 填什么 |
|---|---|
| base_url | 公司 JIRA 网址，跟你浏览器地址栏里的一样，**末尾不要斜杠** |
| username | 你在 JIRA 网页登录用的名字 |
| password | 登录密码 |

> ⚠️ 两个坑：① 尖括号 `<>` 是提示你「这里要换掉」，**别连括号一起留下**；② 这张卡只有你自己知道，别发群里、别发给同事——他们得办自己的卡。

## 第 3 幕 · 试刷一次卡（1 分钟）

```bash
python scripts/jira.py search --jql 'assignee in (currentUser()) order by updated DESC' --max 3
```

这句话的意思是：「查 3 张指派给我的单」。`currentUser()` = 谁运行就查谁，不用改。
（更省事：跑 `python scripts/jira.py init --check`，账号/项目/当前项目一次列给你。）

- 屏幕上出现一张小表格（单号/状态/标题）→ **门禁通了**，以后不用再配置
- 出现 `认证失败 HTTP 401` → 门禁卡填错了，回第 2 幕检查（多半是 `<>` 没删干净）

## 第 4 幕 · 查活：我有哪些没做完的 bug

```bash
python scripts/jira.py search --jql 'resolution = Unresolved AND assignee in (currentUser()) order by updated DESC'
```

多了一个 `resolution = Unresolved`，意思是「只要没解决完的」。你会看到类似：

```
共 21 张（已取 21）
key            | 类型     | 状态      | 优先级       | 更新         | 摘要
STRUCTURING-25 | ST-BUG | 未开始     | Medium-一般 | 2026-09-08 | 【我的空间列表】置顶按钮常显…
```

**默认查「当前活动项目」**（第一次 init 时设的，比如 STRUCTURING）——不切换就一直在它上面干活；想换：`python scripts/jira.py use 项目名`（不带参数看已登记清单）。临时看别的项目也可以把 JQL 开头加上 `project = 项目代号 AND`。

## 第 5 幕 · 读单：这张单写的啥

挑一张，看完整内容（描述 + 测试的评论都在里面）：

```bash
python scripts/jira.py issue STRUCTURING-25 --save bug.md
```

你会看到：谁报的、什么状态、操作步骤、期望结果、实际结果、评论记录。
**大白话读单口诀**：标题里的【方括号】告诉你在哪个页面；「期望 vs 实际」两段对比就是 bug 本身；
「前置条件」里给的账号密码是**测试环境用的**，不是让你拿去登的，更不是要改的代码。

## 第 6 幕 · 改 bug（这段工具不代劳）

工具是「流程员」，管查单/报单/交单；**改代码还是你（或你身边的 AI）在代码仓库里干**：

1. 按【模块】找到代码位置（不会就问 AI：「这个 bug 在哪个文件，帮我改，先给我方案」）
2. 改完自己验证（页面点一遍 / 接口调一遍）
3. 改动只留在你本地工作区，**commit 自己来**

## 第 7 幕 · 交单：两步走

**第一步：接受（相当于网页上点「接受」，单子从「未开始」变「处理中」）**

```bash
python scripts/jira.py start STRUCTURING-25
# → 已流转: 接受 -> Working；读回: STRUCTURING-25 -> Working (resolution=-)
```

**第二步：等测试验收通过后，「解决」+ 填表（重头戏）**

```bash
python scripts/jira.py resolve STRUCTURING-25 \
  --impact "影响范围：这次改动碰了哪些页面/功能，自己写人话" \
  --cause "需求理解偏差" \
  --solution "调整UI/样式" \
  --prevention "无需额外措施" \
  --field "修复的版本=V1.0.0_1"
```

参数大白话：
| 参数 | 大白话 | 怎么填 |
|---|---|---|
| `--impact` | 影响范围 | 自由写：动了哪块、影响谁。**自己填** |
| `--cause` | 发生原因 | 下拉框！只能选命令打印出的词（需求理解偏差/代码逻辑错误/逻辑边界遗漏…），**别自己造词** |
| `--solution` | 解决方法 | 同上，词表里选 |
| `--prevention` | 预防措施 | 同上；拿不准就填「无需额外措施」 |
| `--field "修复的版本=…"` | 版本号 | 填**你们当前要发的版本**（不知道问组长），附加字段都用这个写法 |

屏幕上会依次出现：字段映射 → 词表 → `已流转 STRUCTURING-25: 解决 -> ST Check；读回: …`
填错词会怎样？**当场拦住**，列出能选的词，单子一点没动——放心试。

交完自动转给报 bug 的测试（想转别人加 `--assign "人名"`）。

## 第 7.5 幕 · 顺手接同事的单（可选）

有时同事休假、单归你顶。先探一下这张单你动不动得了：

```bash
python scripts/jira.py transitions T-118
```

- 能列出一堆流转（接受/解决）→ 权限够，照常修。
- 只报一句 `无任何可用流转` → 说明工作流只认经办人。把它接管到你名下：

```bash
python scripts/jira.py assign T-118 --to me
# → 已指派 T-118 → 你的名字；读回 ✓
```

接管 = 把经办人改成你，JIRA 有记录（公开动作，先跟同事打个招呼）。接完照常 start / resolve，交测试或修完还给原主都行。

## 第 8 幕 · 收尾

1. **确认清零**：把第 4 幕的命令再跑一遍 → `共 0 张` = 全处理完
2. **汇报**：`单号 | 改了什么 | 验证结果 | 状态` 一段话发群里
3. 代码 commit 自己来；工具要升级了：`git pull`

## 踩坑速查（同事版）

| 现象 | 大白话原因 | 怎么办 |
|---|---|---|
| `认证失败 401` | 门禁卡填错 | 检查用户名/密码/`<>`；还不行找 JIRA 管理员确认账号支持接口登录 |
| 词表外填词被拦 | 下拉框只能选现成词 | 看它列出的可选项，换个词 |
| 版本号不知道 | — | 问组长当前发版号 |
| 中文变乱码 | 终端太老 | 用 git-bash / PowerShell / VS Code 终端 |
| 「接受/解决」找不到 | 你们项目叫法不同 | 先跑 `transitions 单号` 看叫啥，加 `--transition-id 数字` 指定 |
| 别人的单点不动（无可用流转） | 工作流只让经办人流转 | 先 `assign 单号 --to me` 接过来再流转 |
| 贴了单页链接报「没有 JQL」 | browse 单页链接不含过滤器 | 用列表页 `/issues/?jql=…` 的地址，或直接手写 `--jql` |
| 提示「未设置活动项目」 | 第一次没设当前项目 | 跑 `python scripts/jira.py use 项目名` 选一个 |
| 项目名记不住 | — | 跑 `python scripts/jira.py use` 看清单（带 * 的是当前项目） |
