# 02 · 使用方法

> 全文命令以 `python3 scripts/jira.py` 为例；Windows 下 `python scripts/jira.py` 同理。
> 每个子命令都有 `--help`。全局参数：`--profile 名字`（多实例切换）、`--config 路径`、`--timeout 秒`、`--insecure`。

## 1. 命令参考

### init —— 初始化向导（首次必跑）

```bash
python3 scripts/jira.py init                 # 交互向导：填账号 → 验证 → 勾选登记项目 → 设活动项目
python3 scripts/jira.py init --check         # 只体检（不动配置；返回码 0=已就绪）
python3 scripts/jira.py init --projects "STRUCTURING,BPM" --use STRUCTURING   # 非交互：补登记/换活动项目
python3 scripts/jira.py init --projects all --use STRUCTURING                 # 一键登记全部可见项目
```

- 首次运行：提示输入 JIRA 地址/登录名/密码（密码不回显）→ 现场验证 → 列出实例可见项目供勾选登记 → 设当前活动项目
- 已有配置再跑：只补齐缺失项、更新项目登记（原文件其余内容原样保留）
- 体检输出一眼看清：实例 / 账号 / 认证 OK? / 已登记项目 / 当前活动项目 / 状态

### use —— 查看/切换当前活动项目

```bash
python3 scripts/jira.py use          # 列出已登记项目（* 标记当前活动项目）
python3 scripts/jira.py use BPM      # 切换（也支持序号、前缀模糊：use 22 / use struc）
```

**「不说切换就永远聚焦活动项目」**：`search` 不带条件 = 当前活动项目我的未解决；纯数字单号（`issue 25`）自动补活动项目前缀；操作其他项目的单会提示当前活动项目是什么（防止切错上下文）。没登记过的项目 `use` 时会先到实例校验再自动登记。

### pconfig —— 拉单模板（项目文件夹 / hermes 两层，v2.3）

```bash
# ① 项目文件夹配置（推荐：在项目根目录执行一次，跟着项目走）
python3 scripts/jira.py pconfig --here --set-project STRUCTURING \
  --default-jql 'project = {project} AND status = "Initial" AND assignee in (currentUser()) order by updated DESC'
python3 scripts/jira.py pconfig --here              # 查看当前生效的文件夹配置
python3 scripts/jira.py pconfig --here --clear      # 删除

# ② hermes 项目配置（跨目录兜底）
python3 scripts/jira.py pconfig STRUCTURING --default-jql '…'
python3 scripts/jira.py pconfig STRUCTURING         # 看（含生效顺序）
```

优先级：**项目文件夹（就近 `.jira-project.yaml`）> 项目配置（`hermes/jira-project-configs/<KEY>.yaml`）> 全局配置（凭据文件的 `default_jql`）> 内置默认**。
- 文件夹配置键：`project`（本目录默认项目）/ `default_jql`（模板，含 `{project}`）/ `profile`（可选多实例）
- 从当前目录向上查找；在该目录（含子目录）裸跑 `search`、纯数字单号都以它为准（活动项目自动让位，离开目录恢复）
- 只影响不带条件的默认拉法，不影响手写 JQL；`JIRA_NO_FOLDER_CFG=1` 临时禁用

### whoami —— 我是谁、连的哪台、在哪个项目（冒烟验证首选）

```bash
python3 scripts/jira.py whoami
# 身份: 张三 (name=zhangsan, email=zhangsan@corp.com)
# 实例: https://ticket.你的公司.com（凭据: …\jira-api-creds.yaml，认证: basic）
```

### search —— 拉 bug 清单（工作流第一步）

```bash
python3 scripts/jira.py search --jql 'JQL' [--max 100] [--all] [--format table|json|md] [--fields key,summary,…]
python3 scripts/jira.py search --url 'https://主机/issues/?jql=…'     # 直接贴过滤器链接
```

- 不带任何条件：**当前活动项目里我的未解决**（`project = <活动项目> AND resolution = Unresolved AND assignee in (currentUser())`；可用配置 `default_jql` 改模板）
- `--jql`：原始 JQL（与 `--url`/`--project` 三选一）。示例：
  - 全部未解决且指派给我（最常用）：`resolution = Unresolved AND assignee in (currentUser()) order by updated DESC`
  - 指定项目未开始：`project = X AND status = 未开始 AND assignee in (currentUser()) order by updated DESC`
  - **别人的单**：`assignee = zhangsan AND resolution = Unresolved`（用登录名或显示名）
- `--url`：在 JIRA 页面复制地址栏的**过滤器链接**（`/issues/?jql=…` 那种），JQL 自动提取、自动解码；贴了 `browse/XX-1` 单页链接会提示「不含 JQL」
- `--project KEY`：本次只查该项目（`ALL`=不限项目），**不改活动项目**
- **防跑偏护栏（v2.2）**：手写 `--jql`/`--url` 若未限定 project，**默认被拦截**（报错教你两条路）；查询指向的不是当前活动项目会给提示——确实要跨项目搜索时显式加 `--all-projects`
- `[项目]` 行会标明本次拉单用的**模板来源**（项目文件夹 / 项目配置 / 全局配置 / 内置默认），见 `pconfig`
- `--max`：最多取多少张（默认 100，**超过 100 自动分页**）；`--all`：取全量
- `--format md`：输出 markdown 表格，方便贴给 AI/文档；`json` 输出完整 issues 数组
- 输出表格含「经办人」列——一眼看出哪些是别人名下的单

### issue —— 拉单详情 + 评论 + 附件（AI 读单输入）

```bash
python3 scripts/jira.py issue STRUCTURING-25 [--save D:/tmp/s25.md] [--format md|json]
```

输出：状态/优先级/类型/报告人/经办人/时间 + 描述 + 附件清单 + 评论时间线。`--save` 存成文件供 AI 逐段阅读；附件可用 `attachments` 子命令下载。

### attachments —— 下载附件（截图等）

```bash
python3 scripts/jira.py attachments STRUCTURING-25 [--save-dir 目录] [--id 附件id]
```

默认存到 `./jira-attachments/<KEY>/`；UI 类 bug 的截图下载后可直接给 AI 看图定位。

### transitions —— 查看某单当前可用的状态流转

```bash
python3 scripts/jira.py transitions STRUCTURING-25
# 41	接受	-> Working (category=indeterminate)
# 11	解决	-> ST Check (category=indeterminate)
```

**看到空列表**（`[错误] 当前账号对 X 无任何可用流转`）= 这张单的工作流不让你动（通常是"只有经办人能流转"）——想处理就先接管：`assign X --to me`。

### start —— 「接受」（未开始 → Working）

```bash
python3 scripts/jira.py start STRUCTURING-25 [--dry-run]
# 已流转: 接受 -> Working @ https://ticket.你的公司.com；读回: STRUCTURING-25 -> Working (resolution=-)
```

按名称匹配「接受」类流转（不硬编码 id）；`--dry-run` 只预演。
**安全护栏**：当前状态已不是「未开始」（如已在处理中）时会拒绝执行并列出可用流转（避免误流转）——确要流转用 `--transition-id` 指定。

### resolve —— 流转「解决」+ 填自定义字段 + 转交（核心写操作）

```bash
python3 scripts/jira.py resolve STRUCTURING-25 \
  --impact "影响范围（自由文本）" \
  --cause "发生原因（下拉选项，自动校验）" \
  --solution "解决方法（下拉选项，自动校验）" \
  --prevention "预防措施（下拉选项，自动校验）" \
  [--field "修复的版本=V1.0.0_1"]...   # 附加屏幕字段，可多次
  [--assign "张三"]                    # 解决后显式转交某人（显示名或登录名）
  [--comment "已修复，见提交 abc123"]   # 流转时附带一条评论
  [--transition-id 11]                 # 流转名歧义时强制指定
  [--dry-run]                          # 预演：只打印将发送的 payload+字段清单，零写请求
```

执行过程（全部自动，无硬编码）：
1. 读取该单可用流转，按名称含「解决」选中（目标可能是中间态如 ST Check，不是最终态）
2. 展开流转屏幕字段（`transitions?expand=transitions.fields`），按中文标签匹配四个标准字段；**字段 id 每次运行时发现**
3. select 字段自动打印可选值词表，并校验你传入的值：不在词表 → **请求发出前中止**并列出可选项（避免盲发 400）；标点差异（`、` vs `/`）自动容错
4. 值按字段类型自动包装：选项 → option id；版本 → 数组；用户 → name；文本框 → 原值
5. 必填检查通过后发流转，**自动读回（状态 + 每个已填字段）逐项核对**
6. 如带 `--assign`：再单独 PUT 经办人并读回核对（转交测试/原报告人）

> ⚠️ 词表、字段标签、状态名**因项目而异**——工具每次运行都现场发现，换项目不用改任何代码。**别硬背词表**，以命令输出为准。非中文界面的实例：四个中文标签匹配不上时会有警告，用 `--dry-run` 看屏幕字段实际名称后改用 `--field "字段名=值"` 传。

### assign —— 改经办人（接管 / 转派）

```bash
python3 scripts/jira.py assign STRUCTURING-25 --to me            # 接管（把单转到自己名下）
python3 scripts/jira.py assign STRUCTURING-25 --to "张三"        # 转派给别人（显示名或登录名）
python3 scripts/jira.py assign STRUCTURING-25 --to me --dry-run  # 只预演
# 已指派 STRUCTURING-25 → 张三 (name=zhangsan) @ https://…；读回: 张三 ✓
```

**改别人的 bug 的第一步**：工作流通常只允许经办人流转——先 `assign --to me` 接管，再 start / resolve。干完记得按约定交回或转交测试。
名字匹配不到时会报错并提示（可能是该人不属于本项目 assignable 用户）；匹配到多人时会列出候选名单并中止，改用完整显示名/登录名再试即可（部分实例服务端会忽略查询词、返回全量名单，脚本在客户端过滤兜底）。

### comment —— 加评论（协作 / 交接说明）

```bash
python3 scripts/jira.py comment STRUCTURING-25 --body "已定位，正在修复"
python3 scripts/jira.py comment STRUCTURING-25 --body "[~zhangsan] 帮忙看下这条数据"   # @人：JIRA wiki 语法 [~登录名]
python3 scripts/jira.py comment STRUCTURING-25 --body-file D:/tmp/note.md            # 长内容从文件读
```

执行后按评论 id 读回验证。用户系统若支持，评论会触发邮件通知——**@人之前想清楚**。

### editmeta —— 查看单子可编辑字段 id/必填

```bash
python3 scripts/jira.py editmeta STRUCTURING-25
```

### projects —— 列出可见项目（接入新实例先跑它）

```bash
python3 scripts/jira.py projects [--query 关键词]
```

### fields —— 列出字段（查自定义字段 id/类型）

```bash
python3 scripts/jira.py fields --query 影响范围
# customfield_13209	影响范围	string	custom
```

配合 `--field "标签=值"` 使用；`--dry-run` 里也会打印流转屏幕的全部字段清单。

## 2. 六步数据处理工作流（人 / AI 通用）

| 步骤 | 动作 | 命令或自然语言 |
|---|---|---|
| ① 拉清单 | 按 JQL 拉全量，编号呈现 | `search --jql '…'` / 用户：「拉一下我未解决的 bug」 |
| ② 圈单+读单 | 用户圈定（建议每轮 ≤5 张），逐张拉详情+评论（需要时下载附件看截图） | `issue KEY` / `attachments KEY` / 用户：「1、3、7 分析下根因」 |
| ③ 定位修复 | AI 读单定位代码、给「根因+改法+文件」经确认后修改+自验证；涉及表结构交付 DDL/DML；改动留工作区不提交 | 用户：「这几张都改」 |
| ④ 接受 | 修复验证通过 → 点「接受」（**先 dry-run 预演可选**） | `start KEY` / 用户：「接受吧」 |
| ⑤ 解决 | 用户验收后 → resolve，填影响范围/原因/方法/预防 + 版本，必要时转交（**写前 dry-run 给用户过目**） | `resolve KEY …` / 用户：「这张修好了，流转吧」 |
| ⑥ 收尾汇报 | 单号+根因+改动文件+验证+状态；代码提交由开发者自己做 | — |

**安全约定（写操作三保险）**：start / resolve / assign / comment 永远等用户明说一句再执行 → 执行前可 `--dry-run` 预演（打印完整 payload，零写请求）→ 执行后读回验证。resolve 的具体填值（影响范围写法、原因/方法词表选择）在批量场景先给用户过目或按用户既定默认执行。

**批量场景**（如「把 Working 的全部解决」）：逐张拉详情 → 按 bug 性质归类选词表值（UI 缺失→需求理解偏差/调整UI样式；状态重置/权限遗漏→逻辑边界遗漏/增加边界处理；行为逻辑错→代码逻辑错误/修改业务逻辑）→ 逐张执行并各自读回 → 最后用原 JQL 复跑确认清零。

**改别人的单 / 换实例**：完整场景剧本见 [docs/07-多实例与协作场景.md](07-多实例与协作场景.md)。

## 3. 自然语言触发对照（AI 助手接入用）

| 用户说（大意） | AI 做 |
|---|---|
| 「拉一下我的 bug / 丢 JQL 链接」 | search 拉清单编号呈现，等圈单 |
| 「看下 STRUCTURING-25 什么内容」 | issue KEY 拉详情+评论 |
| 「1、3、7 先分析下根因」 | 逐张详情→代码定位→列根因+改法（**不改码不流转**） |
| 「这几张都改 / 按你分析的改」 | 确认后逐张改码+自验证（不 commit） |
| 「接受吧 / 开始修吧」 | （可先 dry-run）start KEY |
| 「这张修好了，解决/流转吧」 | resolve：影响范围按 bug 写、原因/方法按词表选、预防措施默认「无需额外措施」、修复版本默认团队当前版本 → 读回 |
| 「版本 X / 转给张三 / 预防措施填 Y」 | 覆盖对应参数 |
| 「把 Working 的批量解决」 | 逐张列拟填内容→确认后批量执行 |
| 「我只要 resolve，不用改码」 | 跳过改码直接流转 |
| 「XX 单现在什么状态」 | issue?fields=status + transitions |
| **「初始化 / 第一次用」** | 先 `init --check` 判断是否就绪；未就绪引导用户跑 `init`（或按 docs/01 建配置） |
| **「切到 X 项目 / 现在在哪个项目」** | `use X` 切换 / `use` 查看（whoami 也会显示）；之后默认一直聚焦它 |
| **「这个项目默认只拉 XXX」** | `pconfig KEY --default-jql '…'` 设置项目级拉单模板；`pconfig KEY` 查看 |
| **「在这个目录干活默认就是 X 项目 / 把配置放进项目里」** | 在项目根目录执行 `pconfig --here --set-project X --default-jql '…'`；`pconfig --here` 查看 |
| **「所有项目的都拉一下」（明确要求跨项目）** | `search --jql '…' --all-projects`（未限定 project 的手写查询默认被拦截；AI 不得自行跨项目） |
| **「接一下张三的单 / 这张不是我的，帮我处理」** | 确认后 `assign KEY --to me` 接管 → 正常流程；或先 dry-run 看有没有权限 |
| **「给这张加条评论 / 通知他一下」** | comment KEY（@人用 [~登录名]，先跟用户确认内容） |
| **「这件事跟他交接一下」** | comment 说明 + assign 转派（两步各自读回） |
| **「看看别人手上还有哪些未解决」** | search --jql 'project = X AND resolution = Unresolved'（经办人列直接看） |
| **「换成 XX 环境 / 我另一个账号」** | 加 `--profile 名字`；没有该 profile 就先按 docs/01 建 |

## 4. 完整实测示例

以下为真实项目（中文界面 JIRA Server 8.13）的运行实录，字段 id 与词表为**该项目现场值**，仅作形态示范——你的项目会在运行时自动打印自己的词表。

### 冒烟 + 拉清单

```bash
$ python3 jira.py whoami
身份: 张三 (name=zhangsan, email=zhangsan@corp.com)
实例: https://ticket.example.com（凭据: C:\Users\…\jira-api-creds.yaml，认证: basic）

$ python3 jira.py search --url 'https://ticket.example.com/issues/?jql=project%20%3D%20STRUCTURING%20AND…' --max 30
共 1 张（已取 1）
key             | 类型     | 状态      | 优先级       | 经办人            | 更新         | 摘要
STRUCTURING-119 | ST-BUG | 未开始     | Medium-一般 | Ronnie Li(李一鸣) | 2026-09-10 | 【全局搜索】翻译文档：右侧图片、流程图无法预览
```

  实例: https://ticket.example.com
  账号: zhangsan
  认证: OK（张三）

$ python3 jira.py search --max 5     # 不带条件：默认查活动项目（STRUCTURING）里我的未解决

### `start` 安全护栏实录

```bash
$ python3 jira.py start BPM-1597 --dry-run     # 该单已在处理中，不是「未开始」
[提示] BPM-1597 属于项目 BPM，当前活动项目是 STRUCTURING（如需切换: jira.py use BPM）
[错误] 当前状态「Working」已不是「未开始」，无需「接受」；可用流转: [('11', '解决', 'ST Check'), ('51', 'Pending', 'PENDING')]（确要流转用 --transition-id 指定）
# 不会再误选「解决」等非「接受」流转
```

  可选值: 完善需求文档 / 修改业务逻辑 / … / 调整UI/样式 / … / 其他

  可选值: 完善代码审查Checklist / … / 无需额外措施 / 其他
