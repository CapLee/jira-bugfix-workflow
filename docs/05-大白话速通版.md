# 05 · 大白话速通版（给不想看命令的人）

## 这东西是啥？打个比方

JIRA 上处理 bug 本来要这样：打开网页 → 登录 → 翻列表 → 点开每一张单看内容 → 改完代码 → 再回网页把「解决」按钮点上 → 填一串下拉框 → 转给测试。

这套工具 = 一个**单据机器人**。你跟它说人话：「把我没做完的单拉出来」「25 号单啥内容」「这张修好了，交掉」，它自己跑去 JIRA 查、读、填表、点按钮、转给测试，完事回来告诉你「办好了，状态已经变成 xxx」。

好处：不用开浏览器一个个点；批量几十张单也能一口气办完；它填表前还会先给你看填什么、用词不对会拦下来，不会瞎提交。

## 第一次用：办「门禁卡」（一次性，约 3 分钟）

机器人进公司系统要刷门禁，门禁卡 = 你的 JIRA 账号密码，存在你自己电脑的一个小文件里（叫 `jira-api-creds.yaml`）。三步：

1. **领机器人回家**（只做一次）：
   ```
   git clone https://github.com/CapLee/jira-bugfix-workflow.git
   ```
2. **写门禁卡**：在文件里填三行——JIRA 网址、你的登录名、你的密码
3. **试刷一次卡**：跑一条「查 3 张单」的命令，能列出单子 = 门禁通了，以后不用再弄

> 密码只存在你自己电脑上，机器人不会把它打印出来、不会发到任何地方。

## 以后每天怎么用？三句话的事

| 你想干嘛 | 你就说 | 它做什么 |
|---|---|---|
| 看活 | 「帮我看看我有哪些没做完的 bug」 | 列一张清单：单号、状态、标题，标好 ①②③ |
| 看单 | 「25 号单写的啥」 | 把整张单念给你：谁报的、怎么复现、期望啥样、评论里聊了啥 |
| 改单 | 「1 号和 3 号先分析下怎么改」 | 去代码里找原因，告诉你「毛病出在哪、打算怎么改、动哪个文件」，**等你点头才动手** |
| 交单 | 「这张改好了，交掉吧」 | 自动填表（影响范围/发生原因/解决方法/预防措施/版本号），点「解决」，转给测试，回来报状态 |
| 批量 | 「把处理中的全交了」 | 一张张来，每张先给你看填的内容，你确认后它才交 |
| 接单 | 「张三的单我帮他改」 | 先探路：能动就直接修；动不了先「接管」到你名下（把经办人改成你），修完照常交测试 |
| 换环境 | 「换到 XX 那套 JIRA」 | 一个词切换（`--profile`），并报给你现在连的是哪台 |
| 换项目 | 「切到 BPM 项目」 | 到项目清单里挑（`use`），之后默认一直看你这个项目 |

如果你身边有 AI 助手（比如 Hermes/Claude），以上这些话直接对它说，它替你敲命令——你一个字都不用记。没有 AI 就自己敲三条命令，也就三行字：
```
看清单   → python3 scripts/jira.py search --jql 'resolution = Unresolved AND assignee in (currentUser())'
看详情   → python3 scripts/jira.py issue 单号
交单     → python3 scripts/jira.py resolve 单号 --impact 影响范围 --cause 原因 --solution 方法 --prevention 预防措施
```

## 演示一段（真实单子）

> **你**：拉一下我没做完的 bug
> **机器人**：共 21 张，前几张是——
> ① STRUCTURING-25 我的空间列表：置顶按钮该悬浮才显示，现在一直显示
> ② STRUCTURING-24 语言管理列表：只勾两列时显示有问题
> ③ STRUCTURING-27 我的空间列表：英文界面该显示英文名
> …
>
> **你**：先看看 25 号
> **机器人**：25 号【我的空间列表】置顶按钮……测试 Naomi 报的，期望：没置顶的数据鼠标放上去才出现按钮；实际：全都一直显示着。
>
> **你**：改吧（机器人改完代码并自己验证过）
> **机器人**：25 号改好了：列表页的按钮加了个「是否置顶」的判断，验证通过。要点「接受」吗？
> **你**：接受
> **机器人**：已接受，状态 未开始 → Working ✅
>
> **你**（让测试复测后）：25 号测过了，交掉
> **机器人**：25 号将按以下内容提交：影响范围=我的空间列表置顶按钮显示逻辑；原因=逻辑边界遗漏；方法=增加边界处理；预防=无需额外措施；版本=V1.0.0_1；经办人自动转测试 Naomi。确认？
> **你**：确认
> **机器人**：已解决 → ST Check，转给 Naomi 了 ✅

## 你们常问的（大白话回答）

- **会不会填错/点错？** 它动手前会把「要填什么、转给谁」先报给你听，你确认才提交；下拉框选词不对会当场拦住并告诉你能选哪些，单子不会被改坏。
- **改代码那段谁来做？** 机器人负责 JIRA 上的查/读/填/交；改代码可以由你（或 AI 帮你）在本地改完，改完它帮你走流程。代码提交永远是你自己来，它不碰。
- **安全吗？** 密码在你电脑本地文件里，机器人不打印不上传；传数据走公司内网 HTTPS。
- **别的项目能用吗？** 能。下拉词表、状态叫法每个项目不一样，它每次都是现场去 JIRA 现查的，换项目不用改设置。
- **同事的单我能改吗？** 能。工作流一般只让「经办人」流转——机器人会先探路：能动就直接动；动不了就先把单「接管」过来（经办人改成你），修完交测试或还给同事。接管是公开动作，团队里先打个招呼。
- **同时连两套 JIRA / 换账号？** 一个环境一张「门禁卡」分开放，用 `--profile 名字` 一个词切换；每次干活它都会报「现在连的是哪台」。
- **会不会操作到错误的环境？** 写操作结果里都带「@ 网址」，扫一眼就知道；拿不准先让它「预演」（`--dry-run`，只看不发，连请求都不发）。
- **项目怎么切换？** 第一次用报一次「门」（`init`：账号 + 勾选项目），以后说「切到 BPM」就切（`use BPM`）；不切换就一直在当前项目上干活——连单号都可以只报数字（「25 号单」自动认当前项目）。

## 全功能走一遍（下午茶时间处理 bug 实录）

> 括号里的「小字」是它背地里真正敲的命令，你平时不用记，知道有这回事就行。

**① 看清单（search）**
> 你：看看我今天要干的活
> 机器人：共 21 张未解决——① STRUCTURING-25 置顶按钮常显 ② STRUCTURING-24 语言列表只勾两列显示有问题 ③ …（状态/优先级/谁报的都在表里）
> *小字：search --jql 'resolution = Unresolved AND assignee in (currentUser())'*

**② 换个格式（search --format）**
> 你：给我个能直接贴周报的版本
> 机器人：甩你一张 Markdown 表格（带 | 分隔那种），粘哪都行
> *小字：search … --format md（还有 json 格式给程序用）*

**③ 读单（issue）**
> 你：21 号写的啥？
> 机器人：【我的空间列表-新增空间】选人组件筛选后没清空……Naomi 报的，期望：再次打开要清空；实际：没清空。评论里没有新进展。
> *小字：issue STRUCTURING-21 --save bug.md（存成文件方便 AI 细读）*

**④ 查能转啥（transitions）**
> 你：这张单现在能干什么？
> 机器人：能「接受」（变成处理中），能「解决」（转测试检查）
> *小字：transitions STRUCTURING-21*

**⑤ 改代码** —— 这段由你（或 AI 帮你在本地改），机器人不碰代码，改完只留在你工作区。

**⑥ 点接受（start）**
> 你：21 号我接下了
> 机器人：✅ 已接受：未开始 → Working，读回确认无误
> *小字：start STRUCTURING-21*

**⑦ 看表单能填啥（editmeta，好奇心专用）**
> 你：这单能填哪些格子？
> 机器人：列出所有可编辑字段（名称+是否必填）
> *小字：editmeta KEY——日常用不上，想看字段时用*

**⑧ 交单（resolve 全参数）**
> 你：21 号测试过了，交掉吧
> 机器人：21 号将按这样提交——影响范围=新增空间选人组件筛选重置；原因=逻辑边界遗漏；方法=增加边界处理；预防=无需额外措施；版本=V1.0.0_1；自动转给 Naomi。确认？
> 你：确认
> 机器人：字段已映射 → 词表校验通过 → ✅ 已解决 → ST Check，转给 Naomi
> *小字：resolve STRUCTURING-21 --impact … --cause … --solution … --prevention … --field "修复的版本=V1.0.0_1"*

**⑨ 故意填错试试（词表校验）**
> 你：这张原因填「我也不知道为啥」
> 机器人：⛔ 拦住：原因只能从这些里选：需求文档遗漏 / 需求理解偏差 / 逻辑边界遗漏 / …（单子没被动过，放心）
> *小字：根本到不了提交那一步，填错当场拦*

**⑩ 批量交单**
> 你：剩下处理中的 14 张全交了吧，版本都 V1.0.0_1，预防措施都填「无需额外措施」
> 机器人：好，一张张来，每张内容我先报给你过目——
> …（14 张全部 ✅ 已解决 → ST Check，每张都读回确认）
> *小字：for 循环逐张 resolve（机器人自动跑）*

**⑪ 清零确认（再查一遍）**
> 你：看看还有没有漏的
> 机器人：共 0 张 ✅ 全部处理完
> *小字：把第①步的 search 再跑一遍*

**⑫ 查任意单当前状态**
> 你：3 号现在到哪一步了？
> 机器人：ST Check（测试检查中），解决结果：-；当前能流转：……
> *小字：issue KEY?fields=status + transitions KEY*

**⑬ 帮同事接单（assign）**
> 你：张三休假了，他那几张我先顶着
> 机器人：他名下有 2 张未解决。先探了下路：工作流只让经办人动——我把它们接管到你名下可以吧？（公开动作，单里我会留一句「代为处理」）
> 你：接管吧
> 机器人：✅ T-2、T-3 已转到你名下，评论留痕完成，接下来照常修。
> *小字：transitions 探路 → assign T-2 --to me（可先 --dry-run 预演）*

**⑭ 换一套 JIRA（--profile）**
> 你：切到测试环境那套
> 机器人：✅ 已切换。当前连的是 https://jira-test.example.com，身份还是你。
> *小字：之后每条写操作的结果都会带「@ 网址」，扫一眼就不会串台*

**⑮ 切换活动项目（use）**
> 你：接下来专心看 BPM 了
> 机器人：✅ 已切到 BPM。以后你说「拉一下我的 bug」，我就只查 BPM 里你的单；想看别的项目说一声或者直接报单号就行。
> *小字：use BPM（不带参数=看已登记的项目清单＋当前是哪个；第一次 init 时勾选出来的）*
