# 04 · 端到端实战：从零到改完一张 bug（10 分钟上手）

> 面向第一次使用的同事。全文命令在 Windows git-bash / PowerShell / macOS / Linux 通用
> （Windows 用 `python`，macOS/Linux 用 `python3`，下文以 `python3` 为例）。
> 示例输出取自真实项目（中文界面 JIRA Server 8.13），你的项目词表/状态名会现场自动打印，无需对照修改。

**前提（3 个，缺一不可）**
1. Python 3.8+（`python3 --version` 可查，**无需 pip install 任何东西**）
2. 能访问公司 JIRA（内网/VPN），REST 可直连
3. 你有 JIRA 账号密码（Basic 认证可用；若你登录 JIRA 走 SSO 且无独立密码，先找 JIRA 管理员确认）

---

## 第 0 步 · 安装（一次性，1 分钟）

```bash
git clone https://github.com/CapLee/jira-bugfix-workflow.git
cd jira-bugfix-workflow
python3 scripts/jira.py --help        # 能看到 12 个子命令即成功
```

不想带文档？`scripts/jira.py` 是单文件，拷到任何目录就能跑，这是工具的全部。

## 第 1 步 · 初始化凭据（一次性，2 分钟）

建一个 yaml 文件，三行：

```bash
# git-bash / macOS / Linux
mkdir -p ~/hermes
cat > ~/hermes/jira-api-creds.yaml <<'EOF'
base_url: https://ticket.你的公司.com
username: 你的JIRA登录名
password: 你的密码
EOF

# Windows PowerShell 版
# 文件放 $env:LOCALAPPDATA\hermes\jira-api-creds.yaml，内容同上三行
```

> 路径规则：Windows 默认读 `%LOCALAPPDATA%\hermes\jira-api-creds.yaml`，macOS/Linux 读 `~/hermes/jira-api-creds.yaml`；
> 也可 `export JIRA_CREDS_PATH=/任意路径/creds.yaml` 指到别处；**多套环境**用 profile：`hermes/jira-profiles/<名字>.yaml` + `--profile <名字>`（见 docs/01、docs/07）。
> ⚠️ 别把模板的 `<>` 一起填进去；密码别发聊天/文档。

**冒烟验证：**

```bash
python3 scripts/jira.py whoami
# 身份: 你的名字 (name=…, email=…)
# 实例: https://ticket.你的公司.com（凭据: …，认证: basic）

python3 scripts/jira.py search --jql 'assignee in (currentUser()) order by updated DESC' --max 3
```

成功看到身份行 + 表格即初始化完成。`认证失败 HTTP 401` → 检查账号密码 / `<>` / SSO 锁定（详见 docs/01）。

## 第 2 步 · 查 bug

**① 拉你自己的未解决 bug 清单：**

```bash
python3 scripts/jira.py search --jql 'resolution = Unresolved AND assignee in (currentUser()) order by updated DESC'
# 输出节选
共 21 张（已取 21）
key            | 类型     | 状态      | 优先级       | 经办人            | 更新         | 摘要
STRUCTURING-25 | ST-BUG | 未开始     | Medium-一般 | Ronnie Li(李一鸣) | 2026-09-08 | 【我的空间列表】置顶按钮常显…
```

常用筛选器改 `--jql` 即可（也可以直接贴过滤器链接：`--url 'https://主机/issues/?jql=…'`）：
| 想看什么 | JQL |
|---|---|
| 指派给我的全部未解决 | `resolution = Unresolved AND assignee in (currentUser()) order by updated DESC` |
| 某项目未开始 | `project = X AND status = 未开始 AND assignee in (currentUser())` |
| 某项目处理中 | `project = X AND status = Working AND resolution = Unresolved` |
| **同事名下的单**（帮改） | `assignee = zhangsan AND resolution = Unresolved`（或直接看经办人列） |
| 只要 markdown 表格（贴文档/AI） | 加 `--format md` |

**② 看某张单的完整内容（描述+评论+附件）：**

```bash
python3 scripts/jira.py issue STRUCTURING-25 --save bug.md
python3 scripts/jira.py attachments STRUCTURING-25 --save-dir D:/tmp/att   # UI 类 bug 的截图下载给 AI 看
```

**③ 看某张单现在能流转成什么：**

```bash
python3 scripts/jira.py transitions STRUCTURING-25
# 41	接受	-> Working (category=indeterminate)
# 11	解决	-> ST Check (category=indeterminate)
# （空列表 → 这张单不是你的：先 python3 scripts/jira.py assign STRUCTURING-25 --to me）
```

## 第 3 步 · 改 bug

**模式 A：纯手动** —— 拉详情（上一步②）→ 读单（「前置条件」里的账号密码是测试环境账号，不是要改的代码；按标题【模块】+「期望 vs 实际」定位页面/接口）→ 自己开 IDE 改 → 自己验证。

**模式 B：让 AI 改** —— 把下面两样丢给 AI 即可（推荐）：

> 「读一下 `jira-bugfix-workflow/SKILL.md`（和 `docs/02-使用方法.md`），然后用 `python3 scripts/jira.py` 这套工具，处理我的 JIRA bug。我的代码在 `{你的代码仓库路径}`。先拉我未解决的清单 → 我圈单 → 你逐张拉详情分析「根因+改法+涉及文件」等我确认 → 确认后改码并自验证 → 改动只留工作区，**不要 git commit**；涉及改表/改数据先给我 DDL/DML。写操作（start/resolve/assign/comment）先 `--dry-run` 给我看一眼再执行。」

团队铁律照旧：改动只留工作区（提交开发者自己做）；AI 改完必须自验证（页面/接口/编译）。

## 第 4 步 · 更新 bug 状态

**① 修复完成 → 点「接受」（未开始 → Working）：**

```bash
python3 scripts/jira.py start STRUCTURING-25
# 已流转: 接受 -> Working @ https://ticket.你的公司.com；读回: STRUCTURING-25 -> Working (resolution=-)
```

**② 测试验收 → 流转「解决」+ 填必填字段：**

```bash
# 可选：先预演看一眼会发什么（零写请求）
python3 scripts/jira.py resolve STRUCTURING-25 --impact "…" --cause 需求理解偏差 --solution 调整UI/样式 --prevention 无需额外措施 --dry-run

# 确认后正式执行
python3 scripts/jira.py resolve STRUCTURING-25 \
  --impact "影响范围：自由文本，写清波及的模块/页面/接口" \
  --cause "需求理解偏差" \
  --solution "调整UI/样式" \
  --prevention "无需额外措施" \
  --field "修复的版本=V1.0.0_1"
```

执行过程全自动（输出会逐行告诉你）：
```
字段映射: 影响范围 -> customfield_13209          ← 中文标签→字段 id 现场发现
字段映射: 发生原因 -> customfield_15817
  可选值: 需求文档遗漏 / 需求理解偏差 / …          ← 下拉词表现场打印（示例，以你输出为准）
已流转 STRUCTURING-25: 解决 -> ST Check @ …      ← 自动读回，逐字段核对
[校验] 已读回字段: 影响范围、发生原因、解决方法、预防措施
```

- `--impact/--cause/--solution/--prevention` 四参是团队「解决」必填：影响范围自由写；另三个是下拉，**值必须出自命令打印的词表**（填错会在请求发出前中止并列出可选项，单子不会被改动——放心试）
- 版本、解决方案等屏幕附加字段：`--field "修复的版本=V1.0.0_1"`，多个就写多个 `--field`；不确定填什么就先 `--dry-run` 看「流转屏幕字段清单」
- 转交测试：你们工作流若在「解决」时自动把经办人改为报告人则无需操作；否则加 `--assign "测试员显示名"`

**③ 批量解决（十几张连改）：**

```bash
# 先逐张确认内容（词表值按 bug 性质归类：UI 缺失→需求理解偏差/调整UI样式；
# 状态未重置/权限遗漏→逻辑边界遗漏/增加边界处理；行为逻辑错→代码逻辑错误/修改业务逻辑）
for k in STRUCTURING-21 STRUCTURING-2 STRUCTURING-7; do
  python3 scripts/jira.py resolve "$k" \
    --impact "针对该 bug 的影响范围" \
    --cause "逻辑边界遗漏" --solution "增加边界处理" \
    --prevention "无需额外措施" --field "修复的版本=V1.0.0_1"
done
```

**④ 清零确认：** 复跑第 2 步①的 JQL，`共 0 张` 即全部处理完。

## 第 5 步 · 收尾

- 汇报格式：`单号 | 根因一句话 | 改动文件 | 验证结果 | 当前状态`
- 业务代码提交由你自己 `git commit`；本工具更新：`git pull`

> **帮同事改单 / 换 JIRA 环境 / 多账号**：完整剧本见 [docs/07-多实例与协作场景.md](07-多实例与协作场景.md)。

## 附 1 · 给 AI 用的一句话启动词（可直接复制给同事）

```
你是我的 JIRA bug 处理助手。工具：jira-bugfix-workflow 仓库的 scripts/jira.py（先读 SKILL.md 和 docs/02-使用方法.md）。
流程：用户丢 JQL/链接 → search 拉清单编号呈现 → 用户圈单（≤5张/轮）→ issue 拉详情分析「根因+改法+文件」等确认 → 确认后改码+自验证（不 git commit，涉及表数据给 DDL/DML）→ start 接受 → 用户验收后 resolve（原因/方法取自命令打印的词表，预防措施默认「无需额外措施」，版本按团队当前版本）。
铁律：start/resolve/assign/comment 是写操作，永远等用户明确指令再执行；执行前先 --dry-run 预演、执行后读回验证。单子不是用户的可先 assign --to me 接管。
```

## 附 2 · 命令速查

| 命令 | 干什么 |
|---|---|
| `whoami` | 当前身份/实例（冒烟） |
| `search --jql 'JQL' [--max N] [--all] [--format table\|json\|md]` | 拉清单（自动分页） |
| `search --url '…/issues/?jql=…'` | 贴过滤器链接拉清单 |
| `issue KEY [--save f.md]` | 详情+评论+附件 |
| `attachments KEY [--save-dir 目录]` | 下载附件 |
| `transitions KEY` | 可用状态流转 |
| `start KEY [--transition-id N] [--dry-run]` | 接受 |
| `resolve KEY --impact … --cause … --solution … --prevention … [--field '标签=值'] [--assign 人] [--comment 备注] [--dry-run]` | 解决+填字段+转交 |
| `assign KEY --to me\|姓名 [--dry-run]` | 接管/转派经办人 |
| `comment KEY --body '内容' [--dry-run]` | 加评论 |
| `projects [--query]` / `fields [--query]` | 探查项目 / 字段 |
| `--profile 名字`（全局） | 切换 JIRA 实例 |
| `--config 路径`（全局） | 指定凭据文件（同 JIRA_CREDS_PATH） |
