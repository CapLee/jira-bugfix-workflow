# JIRA Bug 处理助手

**版本 2.5.2**

让 AI 一次读齐工单资料，协助定位修复，按授权批量交接；中断后核对结果继续执行，减少重复评论、上传和流转。

## 能做什么

- 查询当前项目：搜索、详情、评论、附件和变更历史。
- 分析资料包：一次读取多张单，明确标注资料是否完整。
- 协作：建单、指派、评论、附件上传；全部支持写前预演。
- 交付：解决前核实本单修复提交已进入最新远端；批量记录与失败续跑。

## 安装和首次使用

1. 将整个包解压到 AI 助手的技能目录，保留根目录 `SKILL.md` 和 `scripts/`。按宿主要求重新加载技能或新开会话。
2. 安装 Python 3.8+；解决前交付检查需要 Git。公司 JIRA 必须可通过内网/VPN访问。每个人使用自己的 JIRA 账号。
3. 默认地址 `https://ticket.quectel.com`；首次运行 `python <技能目录>/scripts/jira.py init --dialog`，在本机弹窗输入用户名和密码，工具验证 JIRA 身份成功后才保存。密码不回显、不进聊天记录；已有配置直接使用，改密码重跑同一条命令。要设活动项目时才用 `use KEY`。

`<…>` 是占位说明，替换真实值，不要连括号输入。macOS/Linux 可能使用 `python3`。

日常对 AI 说：**“拉一下当前项目我的 Bug。”** 已配置就直接用；也可以说“这几张帮我修一下”或“已修好，流转给测试”。改码不自动流转、不自动提交，只有你明确要求才做。

配置和运行状态默认放在本包 `config/`、`data/`；安装目录需要可写。升级保留这两个目录，重新分享或上传时排除。详细配置和批量例子见 [使用说明](references/usage.md)。

## 安全与适用范围

- 适用于 JIRA Server/Data Center；Jira Cloud 不在本版本支持范围。
- 默认严格校验证书，错误直接停止；公司 CA 可通过操作系统信任库或 `SSL_CERT_FILE` 配置，不自动降低安全设置。
- 凭据本地保存，不包含在发布包中；请设置文件权限，不放共享盘、Git或聊天。
- 只在明确授权后执行写入；有些流转/通知不能无损撤销。已推送不代表已部署。
- 不保证跨机器 exactly-once，不自动提交/推送代码，不承诺所有自定义工作流均可用。
