# JIRA Bug 处理助手

通过 `scripts/jira.py` 读取 JIRA、整理分析资料并执行经授权的流转。Python 标准库单文件，不需要安装其他 Agent 或第三方库；正式解决前需要 Git。适用于 JIRA Server/Data Center；Jira Cloud 不在本版本支持范围。

## 使用前

从业务项目目录运行技能脚本的绝对路径，保留 `.jira-project.yaml` 的就近项目语义。默认 JIRA 地址 `https://ticket.quectel.com`，显式地址和原有账号配置仍优先。首次或认证失效时才检查初始化；已有配置直接做本次任务，不反复要求初始化、输入账号或选择项目。

首次运行 `init` 时，没有单独配置账号就复用 quectel-cli 的 JIRA 插件授权；只保存授权来源，不复制密码或令牌。有效期内无需再输入账号密码，过期明确提示在 CLI 续期；公司 SSO 登录不是 JIRA 授权。没有插件授权时，用户仍可在自己终端通过不回显提示配置账号，禁止在聊天索要密码。默认配置在本包 `config/`，运行记录在 `data/`，升级时保留，分享时排除。

## 日常用法

- 「拉一下我的 Bug / 继续处理」：沿用当前目录和活动项目，只拉当前项目分配给我的未解决单。不要每轮重问项目、账号或整套流程。
- 「看看 / 分析一下」：读齐描述、最后评论、变更历史与必要截图，给根因和建议，不改代码、不流转。
- 「修一下 / 这些都改 / 按你说的改」：范围明确就直接定位、修复、验证，不为了固定数量重复要求圈选；只在真实歧义或方案分歧时问。只留工作区，不顺手接受、解决、评论或提交代码。
- 「我已经修好了，流转给测试」：先核当前状态、实际修复提交和该单报告人，再按授权流转。沿用已确认的项目字段口径，不重复问整套表单；默认逐单交回报告人。
- 「加条备注：……」：把用户原话作为评论发送，不自行扩写；没有明确要求就不额外评论。
- 重开单先看最后一次变更和最新评论；用户已自行修复或流转的单，只补仍缺的动作。

## 工作流

1. `whoami` 核身份与项目；`search` 拉默认队列，不自行跨项目。
2. `triage KEY …` 一次读取圈定单的描述、评论、历史、附件清单和流转；检查每项 `complete/total/fetched/warnings`，不完整不得当成没有记录。需要截图时才下载附件。
3. 用户明确要求改码后定位、修复、验证；遵守业务仓库规范。不自动提交或推送。
4. 只有用户明确说“接受/解决/流转”才执行 start/resolve。“看看/处理/修一下”只到分析、改码与验证，不是流转授权。
5. 正式 resolve 指定 `--repo <业务仓库> --fix-commit <本单实际修复SHA>`，现场核最新远端与干净工作区；默认转给本单报告人。没有证据、未推送、未获授权都停止。已推送不等于已部署或修复正确。
6. 多单用 `batch plan --file input.json`，默认 `batch run <任务文件>` 只预演；明确授权后加 `--execute`。失败用同一任务 `resume`，不删除记录重发。

## 写入安全

- 写前核项目、单号、对象与字段；经授权才接管别人名下的单。
- `--dry-run` 不写 JIRA；没有提交证据的 resolve 预演只用于字段探查，不代表已满足正式交付条件。
- 读回状态、字段和经办人后才能报成功；不确定响应保留记录先核对，不盲重试。
- 已处理阶段不重复流转；同作者完整评论、同名同大小且内容哈希一致附件不重发。
- 被重开或人工转派的旧任务停止重放；不改参数绕过未确认操作。
- 默认严格 TLS 校验，证书错误停止，优先配置公司 CA。不得自行加 `--insecure` 或修改配置跳过校验。
- 凭据、业务资料和执行日志不上传到技能市场；不要复制作者电脑的配置。
